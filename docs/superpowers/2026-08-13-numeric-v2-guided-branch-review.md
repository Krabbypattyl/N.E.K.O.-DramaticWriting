# Numeric v2 引导式支线创作 Review

## 结论

方案有条件通过。保留“终点先行、结局反推、默认不要求作者手算阈值”的总体方向，但必须先把较晚回接的连续性、支线容量和模型权限收紧为可确定性验证的合同。

本 review 只覆盖 NEKO_Numeric_drama 作者侧支线生产，不改变 N.E.K.O 的 Evaluator、Actor、Session、Ledger 或 Runtime 推进职责。

## 当前问题

当前故事地图要求作者手动完成以下工作：

- 创建空幕节点或结局节点；
- 逐条连接路线；
- 理解 `all`、`any`、比较符、阈值和 priority；
- 自己判断支线回接后是否遗漏主线关键事实；
- 自己保证编辑过程不会留下孤立节点或半条路线。

这套流程可以保留为高级编辑能力，但不能作为新作者创建支线的默认路径。

## 通过的产品方向

1. 作者从当前只有一个无条件出口的非结局节点发起“生成支线”。
2. 第一个问题固定为“这条支线最后去哪？”：
   - 回到主线；
   - 通往已有结局；
   - 产生新结局。
3. 选择回到主线后，必须继续询问“回到哪一幕？”。原顺序出口的下一幕默认推荐，较晚节点必须显示被绕过的幕和关键事实。
4. 新结局必须先生成可编辑的结局草稿，作者确认后才根据该终点反推过程。
5. 默认界面只展示人类可读的数值状态和行为依据。正式 metric ID、比较符、阈值、补集和 priority 由服务端确定性计算，只在高级区展示。
6. 模型只生成结局和过程的语义内容；正式 ID、路线、阈值、补集、priority、`min_turns`、编译和原子提交仍由程序负责。
7. 草稿生成、取消或失败不能修改正式 Story Package；只有作者明确应用且编译通过后，才以一个 revision 原子提交。

## 必须修复的风险

### P0：引导式流程不允许“有意改写”被绕过事实

较晚回接时，目标节点和后续主线仍然是固定作者合同。仅让模型声明某项事实被“有意改写”，再让作者勾选确认，并不会同步修改依赖该事实的下游节点，可能产生编译通过但叙事矛盾的故事包。

首版向导只允许 `carried`：

- 每个被绕过节点的 `must_happen`；
- 每条被绕过主线路线的 `transition_contract.must_deliver`；

都必须被放入某个新幕的 `must_happen` 或某次新过渡的 `must_deliver`。服务端把原始事项确定性注入正式合同，不能只相信模型的解释。

需要改写既定事实时，作者退出向导并使用高级手动编辑，同时自行调整下游节点合同。

### P0：回接目标与支线长度必须硬匹配

“建议 1/2/3 幕”不足以阻止作者选择装不下关键事实的长度。`branch-options` 必须为每个回接目标返回：

- `minimum_length`；
- `allowed_lengths`；
- `available`；
- 人类可读的不可用原因。

最低长度由程序依据被绕过幕数和连续性事项数量保守计算。若三幕仍不足以承接，候选在调用模型前禁用。

### P1：不要让模型回传作者已经选定的条件

作者明确选择触发语义时，服务端固定 `condition_key`，模型只解释该状态为何会引出支线。只有作者选择“让生成模型推荐”时，模型才能从服务端提供的候选集合中返回一个 key。

### P1：条件候选必须考虑来源幕的数值节奏

服务端按主线开场到来源幕（包含来源幕）的幕数估算正常节奏可达范围，并用沿途
`recommended_turns × per_turn_limit` 计算理论上限。自动推荐只接收正常节奏可达候选；仅理论可达候选
可以由作者明确选择并显示警告，数学上不可达的候选禁用。高于初始值的中段关系状态使用单侧下界，
关系继续增长仍满足支线，避免幕完成判路前越过 band 上界后反而回到原主线。

### P1：新结局生成必须知道触发语义

新结局模型接收来源状态、作者结局方向和已选的人类可读触发语义，但不接收正式阈值。改变触发语义后，旧结局草稿立即过期，不能继续生成过程。

### P1：默认预览不能变成合同字段清单

默认预览只突出：

- 从哪里分开；
- 在什么剧情状态下触发；
- 中间发生什么；
- 最后回到哪里或进入哪个结局；
- 哪些被绕过事实已经在支线承接；
- 是否存在硬错误。

正式条件、互补表达式、priority 和完整过渡合同放在“高级条件”中。

## 收口后的流程

1. 选择来源节点并点击“生成支线”。
2. 选择终点类型。
3. 回到主线时选择具体回接幕；已有结局时选择具体结局；新结局时填写最终结果。
4. 选择人类可读触发语义，或让生成模型从合法候选中推荐。
5. 填写过程方向。新结局模式下过程偏好可选，结局结果必填。
6. 只显示当前终点允许的 1/2/3 幕长度。
7. 新结局先生成并确认结局草稿；其余模式直接生成过程草稿。
8. 预览“触发 → 过程 → 终点”、被绕过幕和连续性承接结果。
9. 服务端重新校验 revision、上下文指纹、来源资格、条件映射和编译结果。
10. 通过后原子应用；重复提交同一草稿返回同一结果。

## 模型与上下文边界

- 支线输入目标 8K—12K tokens，硬上限 16K tokens；
- 支线过程最多三幕，输出上限 6K tokens；
- 新结局草稿输出上限 2K tokens；
- 候选阶段为尚未填写的作者方向和结局草稿预留预算；调用前再次按实际输入预检；
- 不发送完整项目、无关支线、Session、Ledger、Evaluator 或 Actor 历史；
- 不增加 Planner、自动 Repair、评分模型或隐藏重试；
- 发布前必须使用实际生产模型覆盖三种终点、三种长度、顶部/中间/底部 band、较晚回接和接近上下文上限的压测。

## 实施验收

- 单出口无条件节点可以进入向导，其他来源显示稳定阻断原因；
- 回到主线必须选择具体幕，原下一幕默认推荐；
- 较晚回接只允许完整承接连续性事项，长度不足时不调用模型；
- 作者不需要填写 raw threshold、operator 或 priority；
- 顶部、底部和中间 band 与原主线路线的补集覆盖完整整数范围，且不重叠；
- 作者选定条件时模型不能改选；推荐模式只能返回合法 key；
- 新结局严格为“结局草稿一次 + 作者确认 + 过程草稿一次”；
- 草稿失败、过期、取消、重复应用或并发应用不会创建半成品；
- 应用前通过当前 N.E.K.O Numeric v2.2 编译器；
- Story Package 不包含作者主线顺序、草稿状态或数值语义展示信息。

## 本轮实施结果

上述 P0、P1 已进入当前代码和回归测试：

- 支线入口只接受单个无条件顺序出口；终点先选，回主线必须继续选具体幕；
- 主线回接候选由作者侧 `mainline_node_ids` 决定。旧项目无法唯一推导时，界面只在真实分叉处
  询问作者哪一幕仍属于主线，不调用模型，也不重写路线；
- 每个回接候选返回 `minimum_length`、`allowed_lengths` 和阻断原因，前端只展示装得下连续性事项的长度；
- 固定条件不能被模型改选；推荐模式也只能返回服务端候选 key。正式阈值、补集和 priority 由程序生成；
- 新结局严格分成“生成结局草稿”和“根据作者确认后的结局生成过程”两次显式调用；
- 草稿在应用前不改变正式地图；刷新可恢复草稿，应用前重新校验 revision、指纹、来源和编译结果；
- 连续性首版只接受承接，原始事实由服务端确定性注入，不接受模型声明“有意改写”；
- 已用隔离项目在真实页面覆盖回主线、较晚回接、新结局两段式生成、主线顺序确认、刷新恢复和原子应用。

当前尚未完成新的生产模型正式评分轮。单元、接口和页面闭环通过只证明合同与交互按设计工作；
N.E.K.O 迁移后的两个代表剧本在当前免费端点上已做真实探针，但 Actor 在开场即收到非 JSON 返回，尚未形成可评价换场流畅度的演绎轨迹；
发布前仍需在能够稳定返回结构化 JSON 的实际生产模型上，按“模型与上下文边界”中的矩阵补一轮质量压测。
